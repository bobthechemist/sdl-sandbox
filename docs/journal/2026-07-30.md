# PRD: Dynamic Execution Engine Refactor

## 1. Objective
Refactor the `ExecutionEngine` (`host/ai/execution_engine.py`) to transition from a static, linear execution model to a dynamic, continuous-evaluation loop. This enables external routines to inject new steps into an active plan at runtime (allowing for closed-loop optimizations) without breaking existing linear workflows, violating the immutability of the DLN, or requiring firmware modifications.

## 2. Scope
*   **In Scope:** 
    *   Refactoring `ExecutionEngine.execute_plan` to use a dynamic `while` loop.
    *   Adding an API to the engine for step injection at runtime.
    *   Increasing the verbosity of errors to provide meaningful feedback to user.
    *   Establishing a minimal callback/routing interface for `"host"` device commands (to prevent them from triggering serial timeouts).
    *   Updating `RunCog` to pass the host tools registry into the `ExecutionEngine` upon instantiation.
*   **Out of Scope:** 
    *   Developing specific host-level tools (e.g., `wait`, `optimize`) at this time.
    *   Modifying the broader Cog architecture.
    *   Modifying microcontroller firmware or serial message definitions.
    *   Modifying AI prompts or planner logic.

## 3. Design Principles
*   **Separation of Concerns (SoC):** The `ExecutionEngine` is responsible *only* for iterating through steps, logging progress, and routing commands. The business logic of host tools must remain outside of the engine.
*   **Keep It Simple (KISS):** Avoid complex threading queues or DAGs for the execution plan. Standard lists and index tracking are sufficient.
*   **Backward Compatibility:** A statically defined plan must execute exactly as it did before. The `else` block at the end of the execution loop must be preserved via standard `while...else` syntax.

## 4. Technical Requirements

### 4.1. Execution Loop Refactoring
*   **Current State:** `execute_plan` uses a static `for step_idx, step in enumerate(plan):` loop.
*   **New State:** `execute_plan` must initialize instance-level state tracking and use a `while` loop.
    *   `self.current_plan = plan`
    *   `self.current_step_idx = 0`
    *   `while self.current_step_idx < len(self.current_plan):`
    *   `self.current_step_idx += 1` must occur at the end of every loop iteration.

### 4.2. Dynamic Step Injection API
*   **Requirement:** Provide a public method on the `ExecutionEngine` to append steps mid-execution.
*   **Signature:** `def inject_steps(self, new_steps: list) -> None`
*   **Behavior:** Extends `self.current_plan` with the `new_steps` list. Because the loop condition evaluates `len(self.current_plan)` dynamically, execution will naturally continue into the injected steps.

### 4.3. Local Command Routing (The Callback Interface)
*   **Requirement:** The engine must intercept steps targeting `"host"` and dispatch them locally.
*   **Implementation:** 
    *   Modify `ExecutionEngine.__init__` to accept a `host_tools` dictionary (mapping command strings to callable functions). Defaults to `{}`.
    *   Inside the execution loop, check if `device == "host"`.
    *   If true, look up the command in `self.host_tools`.
    *   Invoke the callback with a standardized signature: `callback(args: dict, plan_id: int, step_idx: int, engine: ExecutionEngine, dln: DigitalLabNotebook)`.
    *   If the command is not found in `host_tools`, abort the plan execution gracefully with a logged error.

### 4.4. State & Logging Integrity
*   **Requirement:** The DLN `step_index` metadata must correctly reflect the sequential execution of the plan, including injected steps. The original `plan` JSON logged to the database must remain immutable.
*   **Implementation:** Because `self.current_step_idx` simply increments inside the `while` loop, dynamically added steps will automatically receive the correct, sequential index ID (e.g., Step 4, Step 5) under the original `plan_id`. DLN `observation` and `system` logs will maintain perfect relational traceability without retroactive modifications.

## 5. Required File Changes

### 5.1. `host/ai/execution_engine.py`
1.  **`__init__`**: Add `host_tools=None` to parameters. Set `self.host_tools = host_tools or {}`.
2.  **`execute_plan`**: 
    *   Bind `plan` to `self.current_plan` and initialize `self.current_step_idx = 0`.
    *   Change the `for` loop to a `while` loop.
    *   Add an `if device == "host":` routing block to handle local callback invocation.
    *   Ensure the index increments safely and the `while...else` success block is preserved.
3.  **`inject_steps`**: Implement `self.current_plan.extend(new_steps)`.

### 5.2. `host/cogs/run_cog.py`
